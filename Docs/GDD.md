# ADDRESS — Game Design Document + Technical Plan (v1.0, 2026-11-17)

> Источник: интервью с автором (этапы 1–5 + финальные ответы). Этот файл — главный документ. Решения здесь важнее любых старых заметок.
> Приоритеты проекта (жёсткие): **P1** безупречное логичное размещение объектов → **P2** максимальная графика при высокой оптимизации → **P3** всё остальное.

## 1. Game Design Document

### 1.1 Концепция
ADDRESS — бесконечное исследование лиминальных пространств от первого лица. Конечной цели, сюжета и объяснений нет. Мир устроен как **Вавилонская библиотека**: у каждого места есть **адрес**, и любое место по своему адресу «всегда существовало». Игрок не побеждает, он **находит**.

- **Чувства:** одиночество и ностальгия (сквозные). Светлые эстетики спокойные и красивые, тёмные страшные.
- **Двигатели интереса** (без сюжета):
  1. **Эхо**: искажённые копии посещённых мест.
  2. **Архив**: фото с очками, редкие находки, родословные копий.
  3. **Поиск по библиотеке**: любая фраза превращается в адрес.

### 1.2 Адрес
- `Адрес = эстетика + seed (64 бит) + поколение Эха + версия генератора`. Текстовая форма: `BR-7F3A-91C2-0D44-E5B1/g0/v1`.
- **Генерация при первом посещении, затем кэш.** Снимок уровня (seed, список размещений, изменения игрока) сохраняется. Повторные загрузки и обновления игры не меняют уже найденное место.
- **Детерминизм.** Один адрес и одна версия генератора всегда дают бит-в-бит тот же мир у любого игрока. Поэтому кооператив и обмен адресами работают без передачи геометрии.
- **Уникальность.** Выход ведёт на новый, ещё не посещённый адрес. Если адрес занят, берётся следующий по детерминированной последовательности.
- **Поиск по фразе.** `seed = hash64(normalize(фраза))`, эстетика определяется весами от hash. Ввод доступен в меню.

### 1.3 Эхо
- `Эхо(g) = Эхо(g−1) + ОДИН шаг искажения`. Шаг = **3 мутации**, выбранные детерминированно по `hash(seed, g)`. Искажение не усиливается, оно накапливается.
- **Мутации:** сдвиг или поворот объекта (с полной проверкой размещения), замена на «похожий» объект из той же семантической группы, сдвиг материала (оттенок, износ), +1 модуль коридора, лишняя или пропавшая дверь, гаснет или мигает лампа, искажение надписей, копия следа игрока (поставленный предмет копируется неправильно), рост влажности или пыли. С g ≥ 4 добавляются **намеренные аномалии** (парение, неправильная гравитация отдельного предмета, повтор комнаты).
- **Сущности:** 1 мутация на поколение (пропорции, скорость анимации, тон голоса, одна поведенческая черта). При высоком g нейтральная сущность может стать опасной.
- Одно место можно скопировать много раз, поэтому образуется **дерево копий (родословная)**. Оно хранится и показывается в Архиве.
- **Возврат** через выход назад ведёт в Эхо g+1, в оригинал вернуться невозможно.
- **Смерть** (на тёмных уровнях): игрока «копирует», он просыпается в Эхе текущего уровня g+1. Game Over нет.
- **Noclip:** выход за геометрию означает падение в «пустоту» (короткая сцена) и попадание на случайный адрес. Изолированных зон не бывает.

### 1.4 Переходы и выходы
- **2–4 выхода на уровень**, каждый ведёт на свой адрес. Гарантия: **хотя бы 1 достижимый выход ВПЕРЁД** (не петля и не тупик).
- **Никаких цепочек условий и квестов.** Выход находят глазами по **визуальной странности**. Открыть его может требоваться физическое действие (отодвинуть, нырнуть, пролезть), но не «принеси ключ».
- **Ложные выходы:** петля в Эхо этого же уровня, переход на опасный уровень, дверь-тупик.
- **Тип выхода ≈ 50% задаёт следующую эстетику** (водный проход ведёт к воде), остальное случайно с весами.
- **Время поиска:** 5–15 мин; «глухие» уровни 20–40 мин.
- **Тихая эскалация** (AI Director): после ~10 мин от настоящего выхода тянет сквозняк (частицы пыли, звук), после ~15 мин мигает ближайшая лампа, после ~20 мин звук становится громче. Маркеров и текста нет.
- **Редкие уровни (~1 из 15–20):**
  - **тихий**: выход проявляется после 60 с без действий;
  - **зеркальный**: выход виден только в отражении или на фото;
  - **пустой**: огромное пустое пространство, одна аномалия;
  - **«выход — это ты»**: лечь, закрыть глаза, повернуться спиной;
  - **«помнящий»**: выход там же, где был в оригинале.

**Каталог выходов по эстетикам** (каждая пара «эстетика × форма» имеет 3–6 визуальных вариантов, поэтому выходы не повторяются):

| Эстетика | Формы выхода |
|---|---|
| Backrooms | дверь без ручки в стене того же цвета; техническая дверь за стеллажом; лифт с одной кнопкой; панель потолка, которая чуть темнее; вентиляция за шкафом; лестница в узкой нише; коридор, который в зеркале продолжается |
| Poolrooms | подводный туннель; лестница, уходящая в воду; слив-воронка; горка, уводящая в темноту; люк на дне; бассейн, в котором отражается другой потолок |
| Frutiger Aero | стеклянный лифт; водная колонна-лифт; пузырь-капсула; трубы пневмопочты; голограмма-дверь в оранжерее |
| Dreamcore / Weirdcore (волна 2) | дверь посреди поля, кровать-портал, окно на полу, лестница в потолок, бесконечный коридор, у которого конец «ближе», когда идёшь спиной |
| Bluehour / город | дверь подъезда с горящим окном, переход-тоннель, телефонная будка, остановка |
| Отель, ТЦ, школа | номер с неправильной цифрой, служебный ход за кассами, шкафчик, лифт без этажа |
| VHS (тёмная) | экран-телевизор, в который входишь; помехи на стене; кассетная дверь |

### 1.5 Эстетики

| Волна | Эстетики |
|---|---|
| **1 (первая версия)** | **Backrooms, Poolrooms, Frutiger Aero** |
| 2 | Dreamcore, Weirdcore, Bluehour |
| 3 | Frutiger Aqua, Old Web (обычные комнаты 2000-х + редкие уровни «внутри экрана»; графика может быть проще) |
| Дополнительно | мёртвый ТЦ, бесконечный отель, школа после уроков, Vaporwave, VHS/аналог (главная тёмная эстетика), дождливый Bluehour-город |
| **Убраны** | Dark Fantasy, Retro Fantasy |

- **Выбор эстетики:** взвешенный бросок по `hash(seed)` с учётом типа выхода.
- **Смешивание:** чистые уровни; переходные зоны у выходов (материалы и свет плавно меняются в сторону следующей эстетики); редкие гибриды.
- **Настроение (mood):** у каждого объекта есть теги стиля и mood (`light`, `neutral`, `dark`). На светлых уровнях объекты `dark` не попадают в пул.
- **Визуальный стиль:** везде фотореализм, характер эстетики задаётся постобработкой и цветом.

### 1.6 Сущности (не входят в первую версию; архитектура закладывается сразу)
- **Опасные** встречаются везде, но на тёмных эстетиках заметно чаще. На светлых: «наблюдатели» (стоят вдали, исчезают).
- Сущность **никогда не перекрывает** гарантированный путь к выходу физически (её патрульная зона исключает критические узкие места).
- Появляются через AI Director (темп, напряжение) и через Эхо (мутации).

### 1.7 Предметы и руки
- **Классы:**

  | Класс | Примеры | Что можно |
  |---|---|---|
  | Мелкий | кружка, бумага | взять одной рукой, осмотреть, бросить, положить |
  | Средний | стул, коробка | нести двумя руками; ходьба медленнее |
  | Тяжёлый | шкаф, стол | только толкать или тянуть |
  | Встроенный | — | не двигается |

- **Удержание пружиной** (physics joint к точке перед камерой): предмет не проходит сквозь стены, отстаёт и выпадает при перегрузке.
- **Осмотр:** вращать предмет у лица.
- **«Поставить»** использует силуэт и **те же проверки размещения**, что и генератор. **«Бросить»** использует свободную физику.
- **Засыпание физики** после остановки предмета. Итоговая позиция пишется в «память уровня» и переходит в Эхо.
- **Защита от эксплойтов:** нельзя стоять на удерживаемом предмете; стопка ящиков, на которую можно залезть, должна быть устойчивой.
- **Защита от блокировки:** если игрок перекрыл **последний** путь вперёд, мир тихо переставляет мешающий объект, пока игрок не смотрит.
- **Инвентарь:** руки, фотоаппарат и 3 кармана для мелких предметов.

### 1.8 Фотоаппарат и Архив
- Фото, сделанное в игре, сохраняется (PNG и метаданные: адрес, g, объекты в кадре).
- **Очки** = Σ(редкость объекта × видимость в кадре, то есть доля пикселей и отсутствие перекрытия) × множитель композиции (объект ближе к центру или к третям, резкость, освещённость).
- **Редкость:** обычные / необычные (1 на уровень) / редкие (1 на 10 уровней) / легендарные (~1 на 500). Попадают в Архив **только через фото**.
- **В Архиве:** фотографии, адреса (копируются одной кнопкой), родословные Эха, коллекция редкостей.

### 1.9 Персонаж
Жёлтый защитный костюм со складками, резиновые перчатки и сапоги, противогаз с двумя фильтрами, ремни и молнии. Модель делается в Blender, скелет совместим с Unity Humanoid.
- **Первое лицо:** видны руки в перчатках и ноги; по краю экрана противогаз и запотевание; глухое дыхание.
- **Кооператив:** напарник видит полное тело.

### 1.10 Интерфейс
- **Главное меню** на фоне живого уровня с медленным пролётом камеры. Пункты: Продолжить, Новый путь, Ввести адрес / фразу, Архив, Кооператив, Настройки, Выход.
- **Карты нет.** На экране только тонкая точка прицела; подсказка взаимодействия — маленький значок рядом с ней.
- **Настройки:** профили Low/Medium/High/Ultra и отдельные параметры, звук, чувствительность мыши, FOV, инверсия, клавиши.

### 1.11 Мультиплеер
- Кооператив на **2 игрока**, через LAN (Wi-Fi или Ethernet, обнаружение по broadcast) или интернет (P2P, ретрансляция через Unity Relay, бесплатный уровень, в будущем Steam).
- По сети передаются только **адрес, позиции игроков, изменения объектов и события**. Мир каждый клиент генерирует сам (детерминизм).

### 1.12 ИИ
- **AI Director** — обычный алгоритм, без нейросетей. Он управляет темпом, тихой эскалацией, редкими событиями и (позже) появлением сущностей.
- **LLM только при разработке:** генерирует сценарии комнат как JSON-данные. Затем слепое сравнение с ручными сценариями (раздел 8). Игра полностью офлайн.

## 2. Архитектура проекта (Unity 6000.4, URP 17.4)

```
Game/Assets/
  ADDRESS/
    Runtime/
      Core/        Address, Rng (PCG/SplitMix, независимые потоки), Hashing, Determinism utils
      World/       LevelSnapshot, LevelCache (диск), EchoChain, AddressBook (посещённые)
      Architecture/ GridLayout (0.25 м), RoomGraph, ModuleKit, ArchitectureBuilder
      Placement/   PlacementProfile, ProfileDatabase, PlacementEngine, Checks/*, SpatialHash,
                   PoissonSampler, ScenarioLibrary, NestedSpawn, AnomalyPlacement, Audit
      Exits/       ExitCatalog, ExitPlanner, ReachabilitySolver, ExitValidator
      Echo/        MutationCatalog, EchoMutator
      Player/      FirstPersonController, GrabSystem, Inspect, PlaceGhost, Pockets, Camera(Photo)
      Director/    AIDirector, Escalation
      Rendering/   QualityProfiles, AestheticPost (Volume), LightingRig
      Net/         (позже) NGO 2.x + Unity Transport, LAN discovery
      UI/          MainMenu, Archive, Settings
    Editor/
      ProfileBuilder   (модель → коллайдеры-вокселы, поверхности, профиль)
      TestFarm         (batchmode: N адресов → аудит → скриншоты → отчёт)
    Data/            profiles/*.json (семантические правила), scenarios/*.json, aesthetics/*.json
  ThirdParty/        PolyHaven/, AmbientCG/  (скачиваются через Tools/fetch_assets.py, не коммитятся)
Tools/  fetch_assets.py, assets_manifest.json, blender/*.py
Docs/   GDD.md, PROGRESS.md, reports/
```

**Принципы:**
- Генерация — **чистые детерминированные функции** от адреса. Все случайности берутся из именованных потоков `rng.Fork("placement/room12")`, поэтому добавление новой системы не сдвигает результат других.
- Данные (профили, сценарии, эстетики) лежат в JSON, код их только интерпретирует.
- Генерация разбита на шаги, которые выполняются асинхронно с бюджетом времени на кадр.

## 4. Спецификация генератора уровней

### 4.1 Архитектура
- **Сетка 0,25 м**, высота этажа 2,7–4,0 м (зависит от эстетики).
- **Кит модулей** (делается в Blender): стены 0,25/0,5/1/2 м, углы 90° и 45°, дуги R1/R2, проёмы, ступени, колонны, потолочные плитки, светильники, плинтусы.
- **Алгоритм:**
  1. BSP или рост комнат по графу (несколько стратегий на эстетику);
  2. коридоры (A* по сетке со штрафом за повороты);
  3. проёмы;
  4. вариации высоты;
  5. **detail-pass**: декали, кабели, пятна, сколы.

  Физика и навигация остаются на ровной сетке, визуальный слой неровный.
- **Размер:** S (20–40 комнат), M (60–150), ∞ (куски 32×32 м). Для ∞ правило: в любом окне 3×3 куска есть достижимый выход вперёд.

### 4.2 Placement Profile (на каждую модель)
Автоматически из меша (ProfileBuilder) плюс ручные семантические правила (JSON):
- `bounds`, `colliders` (воксельная компаунд-аппроксимация 2–3 см, слитая в боксы), `pivot` (низ по центру), `centerOfMass`;
- `supportFace`: floor | surface | wall | ceiling | inside;
- `offersSurfaces[]`: автоматически извлечённые горизонтальные зоны (столешница, полки, сиденье) с высотой, полигоном и свободной высотой над ними;
- `rotation`: free | step90 | step45 | faceWall | faceAnchor; `maxTilt`;
- `clearance`: обязательное свободное место (перед шкафом, у стула);
- `relations`: `near(desk, ≤0.6m, facing)`, `infrontof(monitor)`, `against(wall)`, `under(desk)`;
- `states`: normal | fallen | tilted | broken, с весами и разрешениями сценария;
- `class`: small | medium | heavy | fixed, масса;
- `tags`: стиль, mood, комнаты, семантическая группа (для Эха: «похожий объект»).

### 4.3 PlacementEngine: 9 проверок
Порядок от дешёвых к дорогим:
1. **Bounds:** OBB целиком внутри объёма комнаты или опорной поверхности.
2. **Collision:** `Physics.OverlapBox` по компаунд-коллайдерам с допуском −3 мм; затем точная `ComputePenetration`.
3. **Surface:** raycast вниз из опорных точек; тип попадания совпадает с `supportFace`; нормаль в пределах `maxTilt`.
4. **Support:** ≥ 3 опорные точки в пределах ε = 5 мм от низа; проекция центра масс внутри опорного многоугольника.
5. **Rotation:** верх объекта совпадает с нормалью поверхности; поворот подчиняется правилу.
6. **Semantic:** выполняются relations (клавиатура перед монитором, стул у стола и лицом к нему).
7. **Style:** теги стиля и mood совместимы с уровнем.
8. **Density:** Poisson-радиус через SpatialHash и бюджет на комнату или поверхность.
9. **Navigation:** не занимает зарезервированные клетки проходов (коридоры между проёмами шириной ≥ 0,8 м) и не перекрывает проёмы.

При провале: другая позиция (до K = 12), другой поворот, вариант масштаба ±3% (если разрешено), другая конфигурация. Если ничего не подходит, **объект не ставится**.

### 4.4 Сценарии и вложенный спавн
- **Сценарий** — это JSON-граф: якорь (стол у стены) → дети (стул под столом, монитор на столе, клавиатура перед монитором) → «следы» (кружка, бумаги, отодвинутый стул).
- Оси вариаций: сценарий × тип контейнера × набор содержимого × состояние × раскладка.
- **Вложенный спавн ленивый:** содержимое ящиков и коробок генерируется при открытии из `hash(адрес, id контейнера)`. Глубина ≤ 3.

### 4.5 Намеренные аномалии
Отдельный режим `AnomalyPlacement`, включается только правилом сценария, эстетики или мутации Эха. Каждая аномалия описана явно (парение: высота 0,5–1,5 м, медленное вращение, отсутствие тени снизу заменено на мягкую), поэтому её нельзя спутать с ошибкой. Аудит помечает такие объекты флагом `intentional` и не засчитывает их как ошибки.

### 4.6 Независимый аудит (не верит генератору)
После генерации:
- попарное `ComputePenetration` всех коллайдеров;
- raycast опоры;
- наклон;
- **тест устойчивости**: 2 секунды симуляции физики, и объект, сместившийся больше чем на 1 см или повернувшийся больше чем на 2°, считается неустойчивым;
- проверка проходимости (NavMesh и сетка).

## 5. Система переходов и гарантированная достижимость

1. **ExitPlanner** выбирает кандидатов в узлах RoomGraph с высокой «скрытностью» (дальность от старта по графу, тупики, ниши, вода) и разносит выходы по разным ветвям.
2. **Форма выхода** выбирается из ExitCatalog эстетики с учётом свободного места. У каждой формы есть «отпечаток»: требуемый объём, тип стены или пола, способ прохода (walk, crouch, swim, push).
3. **ReachabilitySolver:** граф клеток с типами переходов (ходьба, присед ≥ 1,0 м, плавание, лестница, толкание тяжёлого объекта, если за ним есть свободное место). BFS от точки спавна до каждого выхода. Хотя бы один выход «вперёд» обязан быть достижим.
4. **Валидация после мебели:** повторная проверка (мебель могла перекрыть путь). Ремонт: убрать самый «дешёвый» мешающий объект → сдвинуть выход → до 3 итераций → новый seed (`seed' = hash(seed, attempt)`, детерминированно).
5. **Каждое поколение Эха** проходит ту же проверку. Мутация, сломавшая путь, отменяется.
6. **Во время игры:** детектор блокировки проверяет путь вперёд, когда изменилась позиция тяжёлого объекта. Если пути нет, объект переставляется вне поля зрения.
7. **Noclip-страховка:** триггер-объём вне геометрии ведёт в «пустоту», а затем на случайный адрес.
8. **Тесты:** TestFarm прогоняет 1000+ случайных адресов, для каждого считает достижимость всех выходов и количество «вперёд» (должно быть ≥ 1 в 100% случаев).

## 7. Архитектура мультиплеера
Netcode for GameObjects 2.x + Unity Transport.
- **Host-client** (один игрок хостит). LAN-обнаружение по UDP broadcast. Интернет через Unity Relay (бесплатный уровень).
- **Синхронизируются:** Address, позиции и анимации игроков, NetworkObject только для тех предметов, к которым прикоснулись (повышаются из статики по требованию), события выходов.
- **Проверка:** клиент сравнивает hash своего снимка с hash хоста. При расхождении получает снимок целиком.

## 8. План сравнения AI и non-AI генерации
- **A — алгоритм:** сценарии вручную плюс процедурные вариации.
- **B — LLM при разработке:** сценарии как JSON, которые проходят тот же валидатор.
- **Метрики:**
  - ошибки аудита на 1000 комнат;
  - разнообразие (энтропия наборов объектов и пространственных паттернов);
  - время генерации;
  - **слепая оценка** скриншотов автором по 1–5 («реалистично», «интересно»).
- Игра поставляется с теми сценариями, которые победили. Во время игры LLM нет.

## 9. План оптимизации
- **URP Forward+**, GPU Resident Drawer + GPU Occlusion Culling (Unity 6), SRP Batcher, **Adaptive Probe Volumes** для GI. Лайтмапы не используются, так как уровни процедурные; APV запекается по шаблонам модулей или используется realtime-аппроксимация.
- **LOD:** LOD Group для мебели (автогенерация в Blender через decimate), импостеры для дальних объектов на ∞-уровнях.
- **Culling:** порталы и комнаты (видимость по RoomGraph), выключение источников света вне видимых комнат, ограничение теней (тени только у N ближайших ламп, остальные без теней).
- **Instancing:** однотипные предметы (бумаги, плитки) через GPU instancing. Статическая архитектура объединяется в меши по комнатам.
- **Pooling** объектов, асинхронная генерация (шаги + бюджет на кадр), стриминг кусков на ∞-уровнях.
- **Коллайдеры:** компаунд-боксы вместо мешей. Физика спит. Слои столкновений.
- **Профили качества:**

  | Параметр | Low | Medium | High | Ultra |
  |---|---|---|---|---|
  | Render scale | 0,67 | 0,85 | 1,0 | 1,0 |
  | Тени | 1 каскад | — | — | 4 каскада, мягкие |
  | Отражения | — | SSR-проба | — | SSR + пробы |
  | Объёмный туман | нет | низкий | средний | высокий |
  | Текстуры | 1K | 2K | 2K | 4K (mip streaming) |
  | Пост-обработка | — | — | — | полная (bloom, DOF при осмотре, зерно) |

- **Целевые показатели:** Intel Arc — High 1080p ≥ 60 fps; RTX 5070 — Ultra ≥ 90 fps.
